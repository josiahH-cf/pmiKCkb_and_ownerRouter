# App-owned date display inventory (S126, F06)

Updated 2026-10-01 UTC. This inventory includes the expanded G3 repair; focused acceptance and full release evidence are recorded in the batch litmus audit. It does not claim remote delivery.

Convention: app-authored calendar dates read MM/DD/YYYY, month-only values use a month name and year, and audit instants retain time and America/Chicago (CST/CDT). Calendar-only values never pass through a time zone. Missing values have an unavailable label; malformed and impossible values have an explicit invalid label. Native date inputs, storage, URLs, sorting, provider payloads and historical receipt hashes retain canonical values.

Shared utility: `lib/date-display.ts`. `formatSourceCalendarDate` validates the documented provider calendar forms (ISO dates/timestamps and MM/DD/YYYY) without rewriting their wire values. `formatBusinessTimestamp` refuses impossible ISO calendar components and malformed instants before JavaScript can normalize them. Boundary tests: `tests/unit/s126-date-display.test.ts`; rendered inventory and cross-lane tests: `tests/unit/s126-date-surfaces.test.tsx` and `tests/unit/s126-additional-date-surfaces.test.tsx`.

The consumer column identifies direct tests where found; otherwise it explicitly distinguishes shared formatter coverage from the complete regression run. New message variables are formatted before display/copy. Immutable current-message snapshots retain their original bytes; legacy own-receipt recovery reconstructs its original formatting and cannot create another draft.
