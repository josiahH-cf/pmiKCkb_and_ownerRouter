# S269 — Put the fields staff need now at the top of Guided work

> Status: AUTHORING READY, intake 147. Companion Guided journey. Implementation and
> verification pending.
> November 12 intake 159 is AUTHORING READY for in-place editing of Rent to recommend and of
> the renewal dates (S281), which replaces the two links named in items 3 and 4 below.

**Goal.**

Staff can tell from the outcome heading what they need to enter, decide or fix, and use
that exact field before reading supporting details.

**Current state / intended end state.**

S247 and S258 already share one set of editors, an outcome-led Guided and Full layout, and
read-only Verification. The current composition can lead with a button and stacked ready
information while the active working fields are lower in the outcome. Some secondary Work
groups default to open in Guided. The walkthrough repeatedly used scroll instructions for
the correction, recommendation, dates and charges. The owner’s follow-up requests stronger
field priority across the entire Guided journey.

**Actors and entry conditions.**

A scoped staff user enters a lease from the Desk, My Work, the existing linked reply, an
authorized procedure or a legacy lease/step link. A permitted Editor can use each existing
action. Read-only roles see the current state and permitted next destination without an
unusable editable field. Existing distinct inspection, wait, terminal and role-limited
states still apply.

**What it is / how it functions.**

From the outcome heading, show a short state and its governing input group or exact fix.
Show the editable field itself when the current outcome owns it and the applicable task is
known. When a prerequisite belongs to a different outcome or role, use its exact route and
give the current reason. Keep the current step cue and existing access to legitimate later
work. After explicit navigation, carry the staff member back to the same lease, cycle,
work context and current field state.

- **R-S269-1 — Use one live priority projection.** Derive the next eligible work, exact
  fix or waiting state from the existing outcome, issue and task ownership. When a blocker
  governs the intended action, the one actionable recovery takes precedence. Active fields
  and necessary context appear before secondary actions and evidence. Use the current
  lease and cycle, read freshness, capability, in-flight save and consequence. A
  later-step inspection can stay selected and retains the current-step cue.
- **R-S269-2 — Elevate current inputs and conditional branches.** Apply the outcome table
  to each standard outcome and variant. Move existing labels, editable fields, minimal
  source/value cue, validation and save/review together near the heading. Put an
  applicable task’s first needed input or exact owner link in the first viewport measured
  from the heading with evidence closed. Choose only the fields needed for the current
  action, and retain an appropriate document/review for longer forms.
  Required-on-this-action and optional must be distinguishable. A previously optional
  field becomes visible if it is now a blocker.
- **R-S269-3 — Keep the exact field through interruptions.** On explicit next/fix
  navigation reveal and focus the owning input or action without operating it. Preserve
  unsaved input and saved revision, selection, pending save, failure and recovery while
  switching Guided/Full, checking evidence, or returning from an existing prerequisite
  within the same case. Keep conflicts and important validation visible. A stale source,
  different lease/cycle or removed permission must not reapply local edits. Do not steal
  focus from a person actively typing during passive refresh.
- **R-S269-4 — Preserve presentation and authority.** Keep Guided as the default where
  already established, one sticky Work status/note/history, verified RentVine and Full
  toggle, five Full sections and exact legacy links. Shared owners and permissions apply
  in both views. Explicit Send, paid lookup, source write, approval or confirmation each
  remains a distinct deliberate step. Use existing layout budgets, visible focus, mobile
  wrapping and both themes.

### Shared Guided layout

Normal entry opens the current step for the exact lease and cycle. Keep the lease
identity, step strip, verified RentVine link, Full toggle and single Work status entry.
From the selected outcome heading, show one short status or decision cue, then the active
input group, exact action or honest wait. When this outcome owns the input, put its actual
label and first editable control in that first viewport and keep the remaining required
inputs, validation and save or review together in work order. The action that follows
entry belongs next to those inputs. Skip a generic opening button for a field already in
the active group. When the field belongs elsewhere, show its exact link with the reason it
is needed. S270 places optional Work and Verification after the active work.

An explicit task or legacy link opens the named outcome and target. View and focus changes
reveal controls and never operate them. A cross-outcome fix keeps the originating task,
lease and cycle. Offer the explicit **Return to tenant offer** from a date fix that
started there, and the equivalent exact return for other supported prerequisite links.
Return to the same work with the refreshed value and any unsubmitted draft intact. After
an explicit later-step visit keep **Show current step**. Refreshing a source does not pull
focus out of an active input.

### Choose the first applicable state in this order

1. Resolve lease/cycle access and applicability. A retired, completed, inspection-only or
   inapplicable outcome shows its actual state and only the independently permitted review
   or recovery. An existing explicit source-based completion decision belongs in the
   active work until decided. A read-only user sees the actual state and exact permitted
   handoff.
2. Reconcile an unresolved previous effect for the intended action. For mail, lead with
   the existing **Check whether the message went out** and the same attempt. This takes
   priority over new missing facts, a draft review or a disabled Send. An in-flight claim
   shows its true status. A verified reply or separately known external action can still
   be recorded through its independently authorized owner, with its own evidence.
3. Keep the active editor's pending save, validation error, failure or stale basis in
   view, with its exact refresh, correction or reconciliation. When current facts for the
   intended task are missing, use the first material input in the outcome order below. A
   missing fact needed only for a different action cannot block independent preparation or
   an authorized record-work path.
4. Show the eligible current editor or exact next action. Use the shared stage, issue and
   readiness projections to choose the action for this outcome. If evidence shows waiting,
   scheduled, paused, covered or done and no actionable answer for that task, lead with
   that state and the next independently available handoff. For a wait, show the party and
   known timing using the existing projection. Keep details and history in the
   disclosures.

These rules order presentation over current action-specific gates. They add no
prerequisite between outcomes and never advance the authoritative stage from a navigation
event.

### Standard outcome field order

1. **Check the numbers → Lease details.** Lead with the first disputed or missing
   prerequisite for current work in this order: current lease identity and term or end
   date, current base rent, a material current charge discrepancy, then a material
   housing-assistance fact. Use the existing current-fact correction and rent-and-charges
   owner here. Show the actual current rent correction field when it is the fix, including
   the competing value or source when needed to decide. Once resolved, show Current base
   rent and Current lease ends as the compact numbers summary, with term or assistance
   status when it changes the path. Use the existing Continue action to the next
   applicable step. A missing **renewal** date is a link to Working renewal terms.
2. **Compare market rent → Market rent comparison.** A usable saved comparison shows
   **Rent to recommend** as the first editable field, with verified current base and the
   saved market estimate or range alongside it. The staff amount stays editable here and
   reads consistently in Ask the owner. If a current independent working base differs, use
   S262's explicit **Use this amount for the offer** review to change it. An edit to the
   recommendation alone leaves the offer basis in place. When the comparison is missing,
   show the explicit permitted **Compare market rent** action, with only a required
   subject correction ahead of it. An unavailable lookup leads with its existing recovery
   or eligible manual recommendation. A usable result puts deliberate rerun and lookup
   inputs below the main work.
3. **Ask the owner → Owner approval.** An eligible actual owner reply, or explicit
   navigation to record a known answer, opens **Record the owner's answer** with Outcome,
   conditional Amount approved, evidence source and the explicit review/save in that
   order. If entered through a date fix, elevate the exact Working renewal terms inputs
   and keep the originating task. Otherwise before outreach show the unresolved pricing
   choice first when the existing rules require a choice. Show the current base and
   Rent to recommend with **Edit**, which opens the one Rent to recommend editor in place
   on this step (amended on November 12, 2026 by owner direction; S281 R-S281-11). Then show the required recipient, sender, or wording fix, or **Review owner
   message**, which opens the existing exact review on the current draft. A verified
   standing agreement that covers the exact case shows its coverage and **Continue to
   Offer the tenant**. A confirmed outreach without a known answer leads with the actual
   wait. Optional delivery methods and staff records follow in S270.
4. **Offer the tenant → Tenant offer and response.** An eligible actual answer leads with
   the existing tenant response editor, outcome and supporting evidence. While preparing,
   show the current-cycle working base and dates in a compact summary. A prior-cycle
   amount or date stays in evidence. An unbound current candidate links to its owner for
   explicit review. First fix the verified current lease-end source if needed for the
   offer. If working base is missing, **Set renewal base rent** leads to Compare market
   rent's existing proposal or manual work, or to the existing assisted or verified
   standing choice when that case governs. Then open a missing working start or end in place on
   this step through the one Working renewal terms editor, where the next-day choice, the
   end choices and manual input are visible (amended on November 12, 2026; S281 R-S281-14
   and S285 R-S285-1). Put **Review offer charges** next, with the first material unresolved
   row or transition choice before the monthly and one-time breakdown. A shared mapping
   need links to the exact Admin handoff. Only after the applicable transition decisions
   are ready does a missing required flyer lead to its resource fix. Otherwise use the
   next recipient, sender or wording fix as needed. A ready offer leads to **Review tenant
   offer**. The existing exact review owns the initial send and bounded follow-up choices.
   A confirmed send awaiting an answer, a scheduled occurrence and a reply-paused sequence
   show their own states. Show the offer a recorded decision answered. An earlier or
   unverified answer stays distinct from acceptance of the current offer, message delivery
   and a reply pause.
5. **Documents and signatures → Documents and completion.** Show the first pending
   applicable packet input or the exact source/authority handoff for that family. A scoped
   editor sees the actual packet input before the form inventory. Once ready, lead with
   the existing review/prepare or manual handoff for this case. During signing wait, show
   what is awaited and use the existing returned-document or human handoff. Provider
   availability never substitutes for actual returned signed evidence.
6. **Finish up → Documents and completion.** Lead with the first applicable outstanding
   task in the existing Finish up projection order. Show its actual input or exact
   source-update review with its consequence. A prepared source change retains its
   separate confirmation. A sent, staff-recorded or verified change uses its true state.
   When no item remains, continue to Complete. Preserve all reachable independent tasks
   and their separate dispositions.
7. **Complete → Documents and completion.** Lead with the existing explicit staff
   completion and its required inputs when available. A later source end-date change that
   qualifies for **Confirm this renewal is finished** offers the existing
   confirm-or-keep-working choice. For a recorded completion show what actually closed and
   its evidence. For an incomplete case show the first exact unfinished action.

### Variant field order

- **Month-to-month review.** Lead with the supported term review and the term or date
  input needed for that review. Use the verified annual or inspection state. The
  fixed-term date suggestion is absent.
- **Non-renewal handoff.** Lead with the existing record or handoff and its applicable
  source or reason. Later standard renewal steps show that they do not apply.
- **Housing assistance.** On Check the numbers, keep ordinary Not set under optional Work.
  A material program indication or an explicit task opens the existing assistance field.
  After Yes, the program contact step leads with the program and exact missing contact
  action, then the assisted owner answer and the rent choice in their existing outcomes.
  Keeping current rent skips the paid comparison and owner rent ask when the existing
  assisted path does so. Proposed change uses that path's verified prerequisites. Existing
  staff-recorded facts remain usable when the future vendor source is pending.
