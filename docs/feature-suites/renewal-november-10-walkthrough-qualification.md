# S271 — Qualify the Thursday fixes, Friday staff review and cumulative renewal journey

> Status: AUTHORING READY, intake 149. Friday review and cumulative verification.
> Implementation and verification pending.

**Goal.**

Use separate evidence for the Thursday correction target, Friday human review and later
cumulative implementation, so each team member knows what passed, what is pending and
which offer or packet can proceed.

**Current state / intended end state.**

The complete November 10 walkthrough is product evidence with actual observed work,
reported defects, demonstrations and proposals. It is not a formal verdict for a
subsequent build. S260’s exact November 9 engineering Yes and staff NOT RUN already exist,
and earlier S254 and S259 retain their actual scopes. This qualification creates new,
separately recorded checks for the November 10 handoff.

**Actors and entry conditions.**

An implementation runner prepares the baseline and drives guarded synthetic and read-only
checks after explicit execution authorization. The renewal lead and any available scoped
staff observer can review a permitted rehearsal. Existing decision-makers supply
source-pending facts through their established channels. Keep real case evidence private.

**What it is / how it functions.**

Before code edits, bind the verified source, deployed behavior, authorized scope, input
references and case fixtures to requirements. Run the Thursday target checks on the exact
core candidate. Prepare a short Friday review using a representative ordinary case, an
exact owner-amount change and relevant exception/readiness cases. For the later cumulative
candidate, rerun the core plus the Guided and follow-on paths on one exact build. Report
verified facts, observed verdicts and pending external inputs separately.
