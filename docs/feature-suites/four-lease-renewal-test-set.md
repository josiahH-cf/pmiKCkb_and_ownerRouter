# S63 — Four-lease renewal operational proof

> Status: The deterministic read-only proof machinery, secure exact-four runtime contracts, and
> value-free command boundary are implemented and deployed. Fresh operational evidence is blocked only because
> no secure four-case runtime packet or observation packet is currently supplied; human review is
> blocked until that fresh report exists.

**Goal.**

Demonstrate on four designated Live leases that the application follows the approved six-step
process and presents defensible reference evidence/decisions while preserving exact identity and
causing no RentVine, Sheet, Dotloop, Gmail draft/send, or other external/client effect and placing no
case identity/value in Git or logs. The only mutation is the exact create-only/append-only app-plane
baseline and evidence record described here.

**Current state / intended end state.**

The runner freezes create-only baselines by lease id, exact Sheet row, timestamp, and source hash;
keeps process, number/evidence, and read-only safety verdicts independent; preflights an observation
batch before its first append; generates a gitignored report; and imports no writer or sender. The
tracked cohort/operator literals and identity-bearing command output have been removed. Exactly four
secure runtime designations and structured observations are required through files outside tracked
source (or under gitignored `temp/`), and commands emit only counts, allowlisted refusal codes, and
opaque run references. The remaining work is operational: supply those secure inputs, perform one
fresh four-case run, and have a real reviewer complete both litmus entries.

**Actors and entry conditions.**

An authorized managed Renewals-space operator supplies exactly four lease-id/Sheet-row bindings
through an approved secure runtime input that is absent from Git and redacted from output. Complete
read-only RentVine/operating-Sheet reads, current source currency, S59 allowance, approved S59/S72
contracts, gitignored evidence output, and closed draft/writer/send keys are mandatory. Missing,
duplicate, ambiguous, or out-of-scope designation blocks capture before any provider read.

**What it is / how it functions.**

Resolve exactly four secure case slots, then capture at most one immutable baseline for each bound
lease. Record append-only observations against that exact identity/hash for: S72 step/substep behavior
and transitions; base-rent and separate-charge truth; S59 exact query basis, returned evidence, and
human decision separation; S77 preview/refusal behavior without confirmation or draft creation; and
every refusal/blocker. Generate process and number verdicts separately. The report contains client
data and remains gitignored; terminal/log output contains only counts and an opaque evidence path/run
reference; Git contains only value-free schemas, criteria, commands, and bodyless completion facts.

**In scope / out of scope.**

In scope: removing current-tree case/operator values, secure exact-four designation validation,
redacted logs, four exact baselines, approved criteria, read-only reference calls, append-only
observations, report generation, human review, and value-free completion record. Out of scope: Git
history rewrite, fixing defects found by the proof in the same evidence record, replacing/recapturing
a baseline, selecting a fifth lease, provider write, client draft/send, action activation, or
committing case values/identities.

**Open questions & assumptions.**

No process/base-rent/radius/count decision blocks evaluation. The four exact secure runtime bindings
must be supplied again outside Git after the tracked literals are removed; existing source literals
are implementation evidence, not authorization to copy them elsewhere. When RentCast does not supply
an age field there is no invented freshness verdict; provider order is retained with no hidden
selection rule. Newly observed lease-specific facts are evidence to review, never guessed defaults.

**Cross-product impacts.**

S59, S72, S77/S74 preview/refusal behavior, RentVine/Sheet reads, immutable baseline/evidence stores,
report generation, redaction, human litmus, facts/status, and future defect suites.
