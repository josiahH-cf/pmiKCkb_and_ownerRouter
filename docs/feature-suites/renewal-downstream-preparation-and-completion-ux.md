**Goal.**

Make the owner-to-completion portion of renewal work use the facts already reviewed earlier, with clear provenance, stable links, readable spacing and a direct path to each genuinely missing input. Prepare messages before recording replies, prevent supported final-body-copy actions from exporting incomplete messages, and keep existing document/manual completion paths usable without inventing provider effects.

**Current state / intended end state.**

`RenewalWorkspace.tsx` currently mounts `RenewalManualSection` before `RenewalMessagePreparation`, placing owner/tenant response controls before message preparation. `current-renewal-message.ts` already loads current-cycle terms, contacts, market preparation and shared resource settings, but charge applicability and signature inputs largely come from the saved manual preparation. `RenewalMessagePreparation.tsx` exposes multiple tightly grouped copy/provider links, an optional response-request edit, manual inputs and a generated missing-input list. It permits copying unfinished bodies with a warning even though the Gmail draft path refuses missing facts.

`renewal-message-content.ts` is the deterministic rich/plain content model for the approved supplied v2 templates. `resource-locations.ts` and `lib/firestore/renewal-resource-locations.ts` already hold Admin-governed, versioned shared resource entries; their full edit panel is mounted inside the lease’s Documents area. `RenewalDocumentHandoff.tsx` and `PacketTruthPanel.tsx` already project packet facts/readiness and manual/provider handoffs. Actual approved legal content, mappings, managed Dotloop readiness and closed-key activation remain external conditions.

The new result is not “more information.” It is fewer duplicated explanations and manual entries, correct chronology, useful field-level provenance and missing-input navigation, and a clear distinction between preparing, copying, saving, confirming, sending elsewhere, recording outside work and provider verification. The capture’s pages 8–19 show this affected downstream surface.

**Actors and entry conditions.**

Existing authorized Renewals readers inspect. Editors retain ordinary preparation/manual recording within the current role matrix, applicable approvers retain their decisions, and Admins retain shared-resource configuration and exact provider/pricing authority. Final addressed email uses the verified source recipient set and current managed sender; no shared connection, signature or status label grants another actor’s identity or confirmation.

**What it is / how it functions.**

### R120.1 — Correct chronology and clearer downstream layout

Present **Market comparison → Owner message preparation → Owner outreach recorded after actual contact → Owner response and exact approved terms → Tenant message preparation → Tenant offer/delivery recorded → Tenant response → Applicable document/follow-up work and completion**. Preserve existing no-response, revision/counteroffer, decline/non-renewal and reopened-work branches; do not make simple visual order a fake provider gate. An actual previously received response can still be recorded through its existing permitted control without inventing prior delivery evidence.

Move owner preparation ahead of the owner response, not merely change the headings. Apply the same preparation-before-response logic to the tenant area. Keep earlier/prior-cycle/provider evidence available in clearly secondary disclosures; it must not look like the current instruction or require the operator to re-enter current terms.

Separate message editing/review, subject/body copy, provider destinations and exact draft confirmation into readable groups with consistent existing spacing, wrapping and hierarchy. Keep the destinations adjacent to their relevant action and clearly labeled—for example, copying an owner message beside the specific owner’s RentVine messages, and tenant copy beside lease messages. Preserve the established dark-mode-readable on-screen preview without changing the approved email/copy styling or adding template text merely for UI contrast. Use S115’s information controls for supplementary prose, not additional dense paragraphs.

### R120.3 — Shared static resources editable in Connections/Admin

Expose management of the existing shared resource entries through the established `/connections` and Admin navigation/task surfaces, using `lib/navigation/admin-connections.ts` and existing configuration capabilities. Reuse the same store, validation, expected version, operation identity and readback—not a second per-lease resource database or a new configuration framework. A renewal operator can follow a specific missing-resource link to its entry or the current access handoff; only the authorized role can edit.

Cover the existing **insurance flyer, Resident Benefits Package flyer, renewal information form**, and all seven legal-location families: **standard lease, renewal extension, animal agreement, lead-based-paint disclosure, city addendum, HOA artifact and owner acknowledgment**. The per-lease workspace should consume/display relevant current links and context-sensitive setup actions, not repeat ten large global configuration forms in every lease. Previously accepted blank pending-team entries remain valid configuration states.

Saving a checked real HTTPS resource location makes it available to the existing dependent projection with its source/version. An empty, invalid, unverified or unavailable setting never becomes a customer link. Preserve the distinction between a failed settings read and a confirmed blank. A URL being present is not proof of its intended content, an approved legal publication, participant/field mapping or a signature. Require only the existing verification/approval boundary, not a new crawler, link-monitoring service or legal-form procurement program. Changing a relevant resource requires review of affected current message content; it does not modify a previously created draft automatically.

### R120.4 — Missing-input navigation and supported final-copy gate

Compute the actual missing requirements for the selected audience/output from the same current content/source/review basis used by its final preparation. Replace the generic count plus universal “Open shared resource link boxes” destination with **specific missing items**, each naming the needed fact/action and linking to the exact field/editor/source/approved-role handoff that resolves it. Open any enclosing disclosure/sidebar, focus the actual input and keep the current lease/audience. Visibly mark genuinely manual required fields with existing attention styling plus a text cue; do not rely only on color.

The captured “four inputs remaining” are not four fixed workflow steps: they were current-rent review, a sourced low/high comparison, comparable evidence or a reviewed attachment, and the current sender’s signature. Their routes are respectively the owning rent/reconciliation editor, comp preparation, the relevant comp/attachment evidence control, and managed sender signature—not all the shared link settings. The count changes with real source state; supplied comp evidence may clear more than one gap. For tenant output, additionally route actual missing owner-approved terms, charge/applicability facts and required resource links to their own controls. Missing approval is not resolved by selecting S119’s status.

**Block supported final body exports while genuinely required content, current review or applicable audience/sender requirements remain missing, conflicting or stale.** Apply the same result to Copy formatted body, Copy plain text and any equivalent supported final-body export/fallback. Style unavailable actions clearly and provide accessible hover/focus help and an adjacent/actionable “Review missing inputs” route. Attempting the guarded action must expose the actual missing items without putting an unfinished body on the clipboard. A disabled-looking button with no reachable explanation does not satisfy this request.

Allow saving/reviewing unfinished preparation and visibly identify an unfinished preview; copying an individually valid subject or a staff-visible factual value need not depend on unrelated body fields. An unfinished selectable-text export must not be an alternate supported path around the body-copy gate. Once final body readiness passes, the existing selectable plain-text fallback remains available if clipboard permission is denied. Do not pretend browser text selection can be cryptographically prevented; this requirement governs the application’s offered final-output controls, not clipboard surveillance.

A genuinely optional omitted field is not a blocker. In particular, the optional response-request wording and optional signature decorations/analysis references do not require invented input. Preserve required applicability/evidence decisions rather than silently treating unknown as optional. Under accepted Q2A, this existing **comparison-based owner message still needs the actual sourced range and real comparable evidence or reviewed attachment**; a rent-derived starting band does not enable copy. The alternate no-comparison final message was not approved.

After the operator resolves a missing item, refresh/recompute the same current basis and actually remove the resolved blocker; do not leave the count/button stuck on an old response. Preserve unsaved edits and require only the existing appropriate re-review. Gmail mailbox/connection/publication readiness remains a separate draft-transport gate; a missing Gmail connection alone must not block otherwise complete locally prepared copy. Recipients from S116 remain complete and audience-separated; do not bypass a recipient gap for an addressed email by dropping a tenant. Requirements for the existing manual portal/text use remain output-specific; email transport readiness must not be imposed on that manual channel.

### R120.5 — Explain exactly what response-request wording does

Keep the optional field but make its purpose explicit in its label/help: it edits the request paragraph in this audience’s generated message. For the **owner**, it replaces the default request following the market-range introduction and before the comparable evidence. For the **tenant**, it replaces the response paragraph after the applicable terms/charges/insurance wording and before the information-form request. Show the current paragraph in the normal message preview so the effect is visible. Blank uses the approved default wording.

This is neither an outgoing request action nor a response record. Saving changes preparation; a person still copies or explicitly creates an unsent draft and sends elsewhere. Preserve the existing bounded wording edit and separate fact fields: rent, dates, contacts, links and charge amounts belong in their source-backed fields, not injected into free prose to bypass validation. Do not change approved template meaning, invent a deadline or add send behavior.

Preserve source-backed links in rich/plain output; attachments remain separate file bytes, with the existing valid receipt/selection and manual download/attach guidance when applicable. Copying must never claim an attachment was transferred or a message sent.

Keep S116’s actual RentVine lease/owner messages and current managed Gmail destinations next to the relevant action. Label a mailbox folder as a folder; use an exact existing draft/thread link only when its destination is actually known. Do not implement RentVine chat posting or general inbox features. Preserve the exact unsent Gmail preview/confirmation, publication, recipient, one-attempt/receipt/readback and reconciliation contracts, including recovery of earlier attempts when the current cycle or inputs have changed. A source refresh is not permission to create a second draft or silently edit an existing one.
