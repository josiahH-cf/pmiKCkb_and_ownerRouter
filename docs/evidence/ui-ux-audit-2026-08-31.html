3 · Scope and evidence

Scope and evidence

The audit covers every discoverable user-facing route and shared shell behavior. It does not claim live-product, product-browser, device, assistive-technology, analytics, or user-research evidence.

Reviewed scope

  • All discoverable page.tsx routes and their primary components.
  • Staff, Admin, Space-scoped, public authentication, and Vendor boundaries.
  • Source-evidenced initial, empty, populated, loading, success, error, unavailable, restricted, destructive, responsive, keyboard, and assistive-technology-relevant states.
  • Shared navigation, tokens, primitives, errors, notifications, confirmation patterns, and current S82–S87 specifications.

Explicitly out of scope

  • Live production interaction, provider calls, data mutation, cloud changes, or client communication.
  • Browser rendering, screenshots, screen-reader execution, contrast certification, or device testing.
  • Claims about actual task frequency, user preference, completion rate, or support volume.
  • Implementation. Reviewer selections below record intent only.
Evidence model, sources, and environment distinctions

Evidence states

  • Verified: implementation or test directly establishes the conclusion.
  • Supported inference: multiple reliable sources strongly indicate the conclusion, but it was not reproduced in a browser.
  • Assumption: provisional and not yet verified.
  • Unknown: insufficient evidence.
  • Contradictory: reliable sources disagree.

Primary sources

  • AGENTS.md, docs/facts.md, and docs/loop-state.md.
  • All 36 route pages, referenced components, route/API guards, CSS, and focused unit tests.
  • docs/feature-suites/guided-renewal-desk-and-workspace.md (S82).
  • docs/feature-suites/unified-admin-access-and-connection-actions.md (S83).
  • docs/feature-suites/navbar-dropdown-navigation.md (S84).
  • docs/feature-suites/global-theme-and-visual-system.md (S85).
  • docs/feature-suites/action-feedback-help-and-safe-recovery.md (S86).
  • docs/feature-suites/content-hierarchy-and-surface-decluttering.md (S87).

Environment and role distinctions

Production is Live-only. Staff roles are Editor, Approver, and Admin; Space claims independently scope Renewals and Maintenance. Vendor sessions are a separate boundary. Navigation visibility never replaces direct route/API authorization.

Time-state clarification

S82–S87 are specified and not implemented. Current code still renders Renewal Authority on renewal surfaces and lacks the later theme, interaction, and content migrations. That is a current-versus-intended state, not a claim that any suite has already shipped.
